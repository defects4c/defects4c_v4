# Defects4C Docker Backend — Validation Service

This is the **C/C++ patch-validation HTTP service** consumed by every Defects4C
APR pipeline in this tree. Containerised FastAPI app at `webapp.py` running on
**host port 8095** (NOT 8090 — that's Defects4J).

If you are a fresh Claude Code session here, also read
`/data/wangjian/wj_code/defects4c_dirs/.claude/CLAUDE.md` for the experiment-tree
context.

## Mission

Receive HTTP `checkout / compile / test / reproduce` requests from APR agents,
execute them inside the container against C/C++ projects, return PASS/FAIL.
The thesis fix-rate numbers in `tab:discuss-overview` all funnel through here.

## ⚠️ Hard rules

1. **Never hand-edit `out/**`** — it is regenerated by `run_reproduce.sh`. Any
   manual changes will be wiped silently. To change behavior, edit
   `defectsc_tpl/**` (live-mounted, takes effect on container restart).
2. **Don't confuse the port** — Defects4C is **8095**. Defects4J is 8090. APR
   agents that hardcode 8090 will silently miss-route to the Java backend.
3. **Don't break the MD5-stamped status invariant** (webapp discipline added
   2026-04-12): `cmd_puretest` writes status files whose path ends with the MD5
   of the patched file's current contents. `trigger_pass=true` is only honored
   when the path's MD5 matches the file just tested. This rule eliminates
   stale-cache false positives — every reproducer/agent depends on it.

## Pool slot architecture (and why it's fragile)

Each bug has 3 pool slots (`__s0`, `__s1`, `__s2`) — independent git checkouts
that callers acquire via `acquire_slot` and release via `cmd_release_slot`.
The locks use `fcntl.flock(LOCK_EX | LOCK_NB)` on `__s{i}.lock` files inside
the container.

**Per-worker isolation gotcha**: `_active_locks` (the in-process dict tracking
fd-keyed locks) lives **inside each gunicorn worker process** (4 workers). If
an HTTP `release_slot` call lands on a different worker than the one that
acquired the lock, the release silently no-ops because that worker doesn't have
the fd. The slot stays locked.

**The only reliable lock recovery is Docker restart** (kills all workers,
closes all fds, releases all flocks):

```bash
cd /data/wangjian/wj_code/defects4c_dirs/defects4c_docker_web4
docker compose restart
until curl -s http://127.0.0.1:8095/health | grep -q ok; do sleep 1; done
```

`/api/release_slot` is best-effort — do not rely on it for recovery from a
killed batch run.

## API endpoints (in `defectsc_tpl/webapp.py`)

| Method · Path | Purpose |
|---|---|
| GET `/health` · `/health/deep` | liveness / readiness |
| POST `/api/exec` | D4J-style CLI bridge (`defects4c <verb>` proxy) |
| POST `/api/exec-shell` | run an arbitrary shell command (with workdir) |
| POST `/api/upload` · GET `/api/download` | file transfer to/from container |
| POST `/checkout` | reset slot to buggy commit |
| POST `/compile` | cmake + ninja in slot |
| POST `/trigger_test` · `/regression_test` | test execution |
| POST `/reproduce` | full clone + build + verify (provisions pool slots) |
| POST `/api/release_slot` | best-effort flock release |
| GET `/list_defects_bugid` · `/get_defect/{id}` | metadata + FL info + prompt |
| POST `/build_patch` | LLM response → patch.diff file |
| POST `/fix` · GET `/status/{handle}` | async patch validation flow |
| GET `/projects` | list known projects |
| POST `/validate_oracle` | oracle correctness check (fix=PASS, buggy=FAIL) |

12 routes total; see `openapi.yaml` for the schema.

## Container management

```bash
make up       # build + start (auto-detect host UID/GID into .env)
make down     # stop & remove
make logs     # follow logs
make restart  # bounce
make health   # curl the health probe
make shell    # interactive shell inside the container
```

The `.env` file is auto-edited by `make init`; first run will create it from
`docker-compose.yaml` defaults if missing. Required vars: `D4C_UID`, `D4C_GID`,
`D4C_PORT` (default 8095). The container internally listens on 11111; the
host port is the publication.

## Consumers (APR pipelines that depend on this service)

All four are HTTP clients of port 8095:

- `agent_apr_d4c/sweagent_selfcontainedqwen_oai/`  ← SWE-Agent
- `agent_apr_d4c/agentless_selfcontainedv2/`        ← Agentless
- `agent_apr_d4c/repairagent_selfcontainedqwen/`    ← RepairAgent
- `agent_apr_d4c/cot_not_agent_baseline/`           ← ReAct

Each consumer's `.claude/CLAUDE.md` documents its specific contract with this
service. If you're modifying webapp.py behavior, **the four consumers must keep
working**; in particular the MD5 status invariant and the slot lock semantics
are not safe to change unilaterally.
